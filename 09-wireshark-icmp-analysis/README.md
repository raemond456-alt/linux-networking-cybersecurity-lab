 # 09 - Wireshark ICMP Analysis

## Objective

The objective of this exercise was to capture and analyze ICMP traffic using Wireshark.

The exercise focused on understanding how the `ping` command generates ICMP Echo Request and Echo Reply packets and how these packets are transported inside IPv4.

---

## Lab Environment

* Testing Machine: Kali Linux
* Target Machine: Ubuntu
* Virtualization: VMware
* Network: Virtual Network
* Packet Analyzer: Wireshark
* Protocol Analyzed: ICMP
* Network Layer Protocol: IPv4

---

## 1. Generating ICMP Traffic

ICMP traffic was generated by sending a ping from the Kali Linux machine to the Ubuntu machine.

The communication between the hosts was:

```text
Kali Linux
192.168.223.129
     |
     | ICMP Echo Request
     v
Ubuntu
192.168.223.131
     |
     | ICMP Echo Reply
     v
Kali Linux
192.168.223.129
```

The Echo Request was sent from Kali to Ubuntu, and Ubuntu responded with an Echo Reply.

## 2. Capturing the Traffic in Wireshark

Wireshark was running on the Kali Linux machine while the ping traffic was generated.

The captured packets included ICMP Echo Request and Echo Reply packets.

The packet list showed communication between:

```text
192.168.223.129 <-> 192.168.223.131
```

The protocol column identified the relevant packets as ICMP.

### Display Filter

The Wireshark display filter for ICMP traffic is:

## 3. Inspecting an ICMP Echo Reply

The selected packet in Wireshark was:

```text
Internet Protocol Version 4
Source:      192.168.223.131
Destination: 192.168.223.129
Protocol:    ICMP
Length:      98 bytes
Info:        Echo (ping) reply
```

This packet was an ICMP Echo Reply sent from the Ubuntu machine back to the Kali Linux machine.

The packet confirms that the Ubuntu host received the Echo Request and responded successfully.

---

## 4. Ethernet Frame

The selected frame was shown as:

```text
Frame: 98 bytes on wire
Interface: eth0
```

The Ethernet frame contained an IPv4 packet.

The packet structure can be represented as:

```text
Ethernet Frame
    |
    +-- IPv4 Packet
            |
            +-- IPv4 Header
            |
            +-- ICMP Packet
                    |
                    +-- ICMP Header
                    |
                    +-- ICMP Data
```

The 98-byte frame consists of the Ethernet frame carrying an 84-byte IPv4 packet.

---

## 5. IPv4 Header Analysis

The selected packet contained the following IPv4 fields:

| Field                   | Value           | Meaning                                     |
| ----------------------- | --------------- | ------------------------------------------- |
| Version                 | 4               | Indicates IPv4                              |
| Header Length           | 20 bytes (5)    | Size of the IPv4 header                     |
| Differentiated Services | 0x00            | No special DSCP/ECN marking                 |
| Total Length            | 84 bytes        | Total size of the IPv4 packet               |
| Identification          | 0x1a6 (57766)   | Identifies the IP packet                    |
| Flags                   | 0x0             | No fragmentation flags set                  |
| Fragment Offset         | 0               | Packet is not fragmented                    |
| Time To Live            | 64              | Maximum number of Layer 3 hops              |
| Protocol                | ICMP (1)        | Identifies ICMP as the upper-layer protocol |
| Source Address          | 192.168.223.131 | Sending host                                |
| Destination Address     | 192.168.223.129 | Receiving host                              |

### Version

The Version field is `4`, indicating that the packet uses IPv4.

### Header Length

The IPv4 header length is 20 bytes.

This is the standard IPv4 header size when no optional IPv4 header fields are present.

### Total Length

The Total Length field is 84 bytes.

This represents the complete IPv4 packet, including the IPv4 header and the ICMP message.

### Identification

The Identification field is:

```text
0x1a6 (57766)
```

This value identifies the IP packet and is particularly relevant when IP fragmentation occurs.

### Flags and Fragment Offset

The Flags field is `0x0` and the Fragment Offset is `0`.

This indicates that the packet is not fragmented.

### Time To Live

The TTL is:

```text
64
```

TTL limits how many Layer 3 hops a packet can make before being discarded.

### Protocol

The Protocol field is:

```text
ICMP (1)
```

This tells the receiving system that the payload of the IPv4 packet contains an ICMP message.

## 6. ICMP Echo Reply Analysis

The ICMP section of the selected packet showed:

```text
Type: Echo (ping) reply (0)
Code: 0
Checksum: 0x196a [correct]
Identifier: 19915 (0x4dcb)
Sequence Number: 1 (0x0001)
```

### ICMP Type

The Type field is:

```text
0
```

ICMP Type 0 represents an Echo Reply.

An Echo Reply is normally sent in response to an ICMP Echo Request generated by the `ping` command.

### ICMP Code

The Code field is:

```text
0
```

This is the normal code value for an ICMP Echo Reply.

### ICMP Checksum

Wireshark reports:

```text
Checksum: 0x196a [correct]
```

This indicates that the ICMP checksum was successfully validated.

### Identifier

The ICMP Identifier is:

```text
19915 (0x4dcb)
```

The identifier helps associate Echo Requests and Echo Replies with the same ping process.

### Sequence Number

The sequence number is:

```text
1 (0x0001)
```

Sequence numbers allow individual Echo Requests and Replies to be matched together.

## 7. Understanding Echo Request and Echo Reply

The normal ICMP ping communication is:

```text
Kali Linux                         Ubuntu
192.168.223.129                    192.168.223.131
       |                                  |
       |---- ICMP Echo Request ---------->|
       |                                  |
       |<--- ICMP Echo Reply -------------|
       |                                  |
```

The Echo Request tests whether the destination host is reachable.

If the destination receives the request and is configured to respond, it sends an Echo Reply back to the originating host.

## 8. Security Relevance

ICMP is commonly used for network diagnostics, but understanding ICMP traffic is also useful in cybersecurity.

Analyzing ICMP traffic can help with:

* Network troubleshooting
* Identifying reachable hosts
* Understanding network communication
* Investigating suspicious traffic
* Detecting unusual ICMP activity
* Learning packet analysis with Wireshark
* Understanding network reconnaissance

Recognizing normal ICMP Echo Request and Echo Reply traffic provides a foundation for identifying abnormal or suspicious network behavior.
